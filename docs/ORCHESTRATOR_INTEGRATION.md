# Orchestrator Integration Guide

## 🎯 Overview

This document explains how the **Orchestrator** (the system that calls this LangGraph agent) should pass data to the intent classifier and how it fits into AgentState.

---

## 📋 What the Orchestrator Needs to Do

The orchestrator should **call the API endpoint** (or directly call `run_graph()`) and pass all the data that will populate the initial `AgentState`.

### Option 1: Via HTTP API (Recommended)
The orchestrator makes an HTTP POST request to `/chat` endpoint.

### Option 2: Direct Function Call
The orchestrator directly calls `run_graph()` function (if running in the same process).

---

## 🔄 Data Flow: Orchestrator → AgentState → Intent Classifier

```
ORCHESTRATOR
    ↓ (passes data)
API ENDPOINT (/chat)
    ↓ (creates)
AgentState (initial)
    ↓ (LangGraph passes automatically)
Intent Classifier Node
    ↓ (reads from AgentState)
Processes user input
```

---

## 📦 What Data Should Orchestrator Pass?

The orchestrator should pass:

1. **`text`** - User's raw input message
2. **`session_id`** - Conversation session identifier
3. **`uuid`** - Request UUID (generated by orchestrator) - **NEW**
4. **`domain`** - Domain context (e.g., "claims", "prescriptions") - **NEW**
5. **`user_info`** - User metadata (user_id, profile, etc.)
6. **`normalized_data`** (optional) - Any pre-processed/normalized data - **NEW**

## 🎬 How Intent Classifier Receives Data

The intent classifier **automatically receives the full AgentState** from LangGraph. It doesn't need to be passed explicitly.

### Intent Classifier Node

```python
async def intent_agent_node(state: AgentState) -> Dict[str, Any]:
    """
    Intent Classifier Node
    
    Receives FULL AgentState automatically from LangGraph.
    Can read ANY field from state.
    """
    # Read user input
    text = state.get("text")                    # User's message
    session_id = state.get("session_id")         # Session ID
    
    # Read orchestrator data
    request_uuid = state.get("uuid")            # ← UUID from orchestrator
    domain = state.get("domain")                # ← Domain from orchestrator
    normalized_data = state.get("metadata", {}).get("normalized_data")  # ← Normalized data
    
    # Read user info
    user_info = state.get("user_info", {})
    user_id = user_info.get("user_id")
    
    # Read conversation history (if available)
    conversation_history = state.get("conversation_history", [])
    
    # Do intent classification...
    # (uses text, domain, normalized_data, conversation_history)
    
    # Return partial update
    return {
        "intent": "claim_status",
        "confidence": 0.95,
        "entities": {"claim_number": "12345"}
    }
```

**Key Point**: The intent classifier doesn't need to be "passed" the data - it **reads from AgentState** which LangGraph automatically provides.

## 🎯 Key Points

### 1. Orchestrator Doesn't Create AgentState
- Orchestrator **passes data** (text, uuid, domain, etc.)
- **This system** creates AgentState from that data
- Orchestrator doesn't need to know about AgentState structure

### 2. Orchestrator Doesn't Pass State to Intent Classifier
- Orchestrator calls API endpoint or `run_graph()`
- LangGraph **automatically** passes AgentState to intent classifier
- Intent classifier reads from AgentState

### 3. Intent Classifier Receives Full AgentState
- Intent classifier gets **everything** in AgentState
- It can read: `text`, `uuid`, `domain`, `user_info`, `normalized_data`, etc.
- It doesn't need to be "passed" anything explicitly

### 4. Data Flow is One-Way (Orchestrator → System)
- Orchestrator → API → AgentState → Intent Classifier
- Intent classifier doesn't call back to orchestrator
- All communication is through AgentState

## ✅ Summary

1. **Orchestrator passes data** via API or direct function call
2. **System creates AgentState** from orchestrator data
3. **LangGraph automatically passes** AgentState to intent classifier
4. **Intent classifier reads** from AgentState (doesn't need explicit parameters)
5. **No manual state passing** - LangGraph handles it automatically

**The orchestrator just needs to call the API with the right fields, and everything else happens automatically!**
